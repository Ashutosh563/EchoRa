1. Product Vision & Executive Overview

SONORA is an AI-native emotive music discovery and mood transition engine. Traditional music platforms depend on generic genre buckets or static query matching. SONORA treats music search as an emotional dialogue, taking natural language descriptions, facial webcam telemetry, and 4-stage psychological transitions to curate hyper-relevant soundscapes via Google Gemini and Spotify.

🌌 Aurora Nocturne Design System

Dynamic 3-layer generative canvas with dark void glassmorphism, responsive ambient glow matching user mood intent, and crisp high-contrast white typography.

⚡ Fluid Micro-Interactions

Framer Motion spring physics for pill-based tab navigation (layoutId="activeTabBadge") and seamless fade/slide transitions when switching between modules.

🌉 4-Stage Mood Transition

Constructs a psycholinguistic bridge from a starting emotion (e.g., Melancholy) to a target emotion (e.g., Serene Joy) across 4 structured stepping stones.

🟢 Native Spotify Integration

Direct track redirection to Spotify, bypassing fragile in-app web players and Spotify guest-mode playlist creation restrictions for a zero-friction listening experience.

Typography Rules

  • Technical Metadata & Counters: JetBrains Mono (font-mono text-xs) for durations, character limits (28/300), and stage indices (01 — Starting Mood).

3. Component Hierarchy & Key UI/UX Evolutions

A. TopBar Navigation (`TopBar.tsx`)

Streamlined, Focused Top Navigation Removed distracting status pills (Live/Mock mode pill) and redundant Spotify authentication buttons from the top bar. Instead, the top navigation focuses strictly on: 1. Brand Wordmark with animated soundwave bars. 2. Fluid center navigation pills between Discover and Mood Transition. 3. Contextual Taste Preferences trigger (visible only when in Discover mode).

The tab pill uses Framer Motion's layoutId="activeTabBadge":

// Sliding pill background indicator across tabs
{activeTab === 'discover' && (
  <motion.span
    layoutId="activeTabBadge"
    className="absolute inset-0 rounded-full bg-gradient-to-r from-violet/90 to-magenta/80 shadow-md shadow-violet/20"
    transition={{ type: 'spring', bounce: 0.18, duration: 0.45 }}
  />
)}

B. Main View Transition (`App.tsx`)

When switching between the Discover interface and Mood Transition page, the content smoothly animates without layout jank or unmounting delays:

<motion.div
  key={activeTab === 'transition' ? 'transition-view' : 'discover-view'}
  initial={{ opacity: 0, y: 14 }}
  animate={{ opacity: 1, y: 0 }}
  transition={{ duration: 0.28, ease: [0.16, 1, 0.3, 1] }}
  className="w-full flex-1 flex flex-col"
>
  {activeTab === 'transition' ? <MoodTransitionPage /> : <Hero ... />}
</motion.div>

C. Mood Transition Module (`LayeredPlaylistView.tsx`)

Architectural Decision: Removal of In-App Player & Playlist Creation

Spotify's Web API imposes severe sandbox limitations on creating playlists programmatically for guest/non-collaborative users. In-app audio previews also fail whenever Spotify removes 30-second preview URLs (a common recent Spotify API deprecation).

UX Improvement Applied:

  • Removed floating bottom audio player bar: eliminates buggy audio element state and broken playback loops.
  • Removed "Play Entire Journey" button: prevents false expectations of bulk playlist creation.
  • Direct Spotify Play Actions: Every track row includes a prominent, animated Play button that redirects straight to track.spotifyUrl in a new tab with official metadata.
  • Retained "New Journey" Flow: Users can effortlessly re-run or re-tune their emotional trajectory.

4. The 4-Stage Psychological Emotional Model

SONORA guides users across a graduated continuum rather than an abrupt sonic change:

Stage Phase Name Color Accent Curatorial Purpose
Stage 01 Starting Mood Violet (#8B5CF6) Validates the user's current feeling; empathetic resonance and acoustic familiarity.
Stage 02 First Transition Indigo (#6366F1) Introduces subtle tempo or instrumentation shifts; opens up emotional breathing room.
Stage 03 Second Transition Cyan (#06B6D4) Builds energetic momentum or harmonic warmth towards the desired state.
Stage 04 Destination Mood Magenta (#EC4899) Full sonic arrival into target state (euphoria, deep focus, relief, peacefulness).

📋 SYSTEM PROMPT FOR CLAUDE: SONORA FRONTEND & UX ARCHITECT

You are the Lead UI/UX Engineer and Frontend Architect for SONORA, an AI-powered emotional music discovery platform. You write production-grade TypeScript, React 19, Tailwind CSS, and Framer Motion code.

Design System Guidelines ("Aurora Nocturne"):

  • Palette: Void Ink (#07070D), Glass Surface (#12121E/80), Electric Violet (#8B5CF6), Cyan (#06B6D4), Magenta (#EC4899), and Spotify Emerald (#10B981).
  • Legibility & Contrast: Always keep text inputs and critical labels in high-contrast white (text-white font-medium, placeholder:text-white/80). Avoid muted or muddy grays over dark aurora backgrounds.
  • Glassmorphism: Combine backdrop-blur-xl with translucent white hairline borders (border-white/[0.08] to border-white/15) and soft drop shadows.
  • Typography: Sora / Space Grotesk for expressive display titles, Inter for body copy, JetBrains Mono for counters, durations, and technical labels.

Key Architectural Decisions to Maintain:

  • TopBar: Keep it clean and streamlined. Only display the Wordmark, center fluid navigation tabs (Discover vs. Mood Transition), and contextual Taste Preferences button. Do NOT re-add mock mode pills or nav Spotify connect buttons.
  • Tab Animations: Use Framer Motion's layoutId="activeTabBadge" on tab buttons for fluid spring-based pill gliding, and smooth entrance/exit animations on active views.
  • Mood Transition Playback: Do NOT implement fragile custom HTML5 audio elements or "Play Entire Journey" playlist creation buttons (Spotify API guest limits). All play actions must open the track's spotifyUrl directly in a new tab (target="_blank" rel="noopener noreferrer").
  • Testing & Type Safety: Always preserve 100% passing tests (Vitest + React Testing Library) and strict TypeScript validation (tsc --noEmit). Never break existing integration test assertions.
